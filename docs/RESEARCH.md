## تصمیم در Pixora 0.5.0

برای هاستی که فایل‌های استاتیک را بدون اعمال قواعد Apache تحویل می‌دهد، موتور «کاهش دیسک با حفظ فرمت» افزوده شد. JPEG همان JPEG و PNG همان PNG باقی می‌ماند؛ مسیر، پسوند، MIME، شناسهٔ پیوست و ابعاد ثابت‌اند. فایل موقت در همان پوشه ساخته، نوع و ابعاد و اندازه‌اش بررسی و فقط اگر کوچک‌تر باشد با rename اتمی لینوکس جایگزین می‌شود. نسخهٔ بزرگ قبلی روی دیسک نگهداری نمی‌شود؛ تأیید داشتن بکاپ مستقل لازم است. هیچ قانون هدایت و درخواست HTTP برای این موتور لازم نیست.

WebP یک گزینهٔ جدا می‌ماند. فایل‌های WebP قبلی حذف نمی‌شوند، چون ممکن است در محتوای منتشرشده مرجع داشته باشند. برای تصاویر قبلاً تبدیل‌شده، موتور جدید می‌تواند JPEG/PNGهای باقی‌مانده را کوچک کند و آمار واقعی این کاهش را گزارش دهد. این کار معادل حذف همهٔ نسخه‌های قدیمی WebP نیست.

## شواهد آزمون

وردپرس واقعی 7.1.4، PHP 8.2.35، MariaDB، Apache برای PHP و Nginx برای تصاویر استاتیک؛ Nginx عمداً htaccess را نادیده گرفت. شکست همان بررسی مسیر قبلی بازتولید شد، سپس موتور هم‌فرمت در همان نصب کار کرد. هنگام خود فشرده‌سازی، همهٔ درخواست‌های HTTP با یک فیلتر مسدود شدند و عملیات همچنان موفق بود.

- JPEG آزمایشی با کیفیت اولیهٔ 100، به‌همراه اندازه‌های وردپرس: **192714 → 53234 بایت**.
- PNG آزمایشی بدون فشرده‌سازی اولیه، به‌همراه اندازه‌ها: **1397165 → 53185 بایت**؛ هش تمام پیکسل‌های RGBA تصویر اصلی در این نمونه ثابت ماند.
- آدرس و نوع محتوای قبلی از Nginx پاسخ 200 و بایت‌های فایل جدید را برگرداند.
- کلیک تکراری به بازفشرده‌سازی و افت کیفیت مجدد منجر نشد.
- خطای نوشتن متادیتا و فایل فقط‌خواندنی باعث حفظ بایت‌های قبلی شدند.
- آپلود خودکار از موتور انتخاب‌شده استفاده کرد و WebP جدید نساخت.

این نمونه‌ها عمداً قابل فشرده‌سازی‌اند؛ اعداد درصدِ وعده‌داده‌شده برای همهٔ تصاویر نیستند. PNG از قبل بهینه ممکن است کاهش نداشته باشد و بدون تغییر باقی بماند. آزمون مقصد کاربر هنوز انجام نشده است؛ این نتیجه تأیید نصب محلیِ مشابه محدودیت گزارش‌شده است.
